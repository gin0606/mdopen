# mdopen

[English](README.md)

Markdown を HTML 1 枚に変換して、その置き場を返す。

```
mdhtml file.md
```

Finder で md ファイルを `mdopen.app` に渡すと、変換して既定のブラウザで開く。

## インストール

`mdhtml` コマンドを入れる:

```
brew install gin0606/tap/mdhtml
```

`mdopen.app` は Finder から開くときだけ要るもので、別の cask になっている:

```
brew install --cask gin0606/tap/mdopen
```

`mdopen.app` は md ファイルの既定のアプリにはならないので、macOS が元から使っているアプリのままになる。「このアプリケーションで開く」から選ぶか、アプリにファイルをドロップする。

## 制限

いずれも設計上の選択で、知らずに使うと驚くもの。

- 生の HTML は許可リストに沿って通す。`<details>`、`<br>`、`<img>` などの無害なタグは残し、`<script>`、`<iframe>`、`on*` 属性、`style` 属性などは取り除く。変換したページを `file://` で開くため、これらを通すとローカルファイルを読める文脈でスクリプトが実行されてしまう。取り除いたタグ・属性はページの先頭の警告に列挙する。文中で触れただけの `<script>` のような閉じていない生の HTML は、以降の本文を消してしまう場合、テキストとして表示する。`<code>` のように見た目を変えるだけのタグは、閉じていなければ以降の本文にもその見た目が及ぶ
- リンクと画像の URL は一般的なスキーム (http、https、mailto、file など) に限る。`obsidian://` や `vscode://` のような独自スキームのリンクは、Markdown で書いたものでもリンク先が落ちる。`data:` URL は PNG・GIF・JPEG・WebP の画像にだけ許す
- mermaid の図を含む文書を開くと、描画ライブラリを jsdelivr から取得する。取得内容は SRI で固定しているが、接続そのものは発生する。図を含まない文書では JavaScript を一切読み込まない
- 変換したページには CSP を付け、実行できるスクリプトを mermaid の描画ライブラリとその起動スクリプトだけに絞る (図を含まない文書では何も許さない)。万一スクリプトが出力に紛れ込んでも、ブラウザが実行を拒否する
- 画像は埋め込まずに参照する。元のファイルを移動・削除すると、ページの表示も壊れる
- 出力は自動削除しない。所有者だけが読める権限で `$TMPDIR/mdopen/` に残り続ける
